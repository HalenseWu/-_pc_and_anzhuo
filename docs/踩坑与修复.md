# 无涯 · 踩坑与修复记录

这份文档记录开发过程中真实踩到的坑：**现象 → 根因 → 修复**。按主题分组，标注首次修复的版本。
多数问题不是"写错一行代码"，而是**平台机制不熟**或**测量时机不对**，希望后来者少走弯路。

---

## 一、排版与分页（最容易被误判为"玄学"）

### #1 首次进入正文被挤压、行宽不对

- **现象**：刚打开书时文字挤在一条窄列里，重新调整字号才恢复正常。
- **根因**：分页测量发生在字体加载完成之前。回退字体的字宽与最终字体不同，`column-width` 与页数全部算错。
- **修复**：等 `document.fonts.ready` 再测量；`columnWidth = 舞台宽度 - 左右边距`，并把该值同时用于页数与 `translateX` 步长。

### #2 换字号后进度错乱、页数越算越离谱

- **现象**：调大字号后当前页跳到别处，或页数显示成 1。
- **根因**：页数用 `scrollWidth / 页面宽度` 估算，忽略了 `column-gap`；且测量时内容还在旧布局。
- **修复**：`total = round((scrollWidth + gap) / (contentWidth + gap))`；测量放进 `useLayoutEffect`，依赖包含字号/行距/字体/边距/内容宽度；测量后 clamp 当前页。

### #3 切换滚动 ↔ 翻页后正文空白

- **现象**：从滚动切回翻页，纸张空白，什么都没渲染。
- **根因**：舞台尺寸只在组件挂载时测量一次。滚动模式下舞台元素不存在，`stageRef.current` 为 null 直接返回，`contentWidth` 一直是 0，于是 `contentWidth > 0 ? <flow/> : null` 永远为 null。
- **修复**：测量 effect 依赖 `scrollMode`，舞台不存在时先清零，挂载后再测。

### #4 分页模式没有章节标题

- **现象**：滚动模式每章开头有标题，分页模式没有。
- **根因**：切章时标题作为"章节首行"被剥离，分页流里只渲染了段落。
- **修复**：把标题作为流内第一个块 `<h2 className="rd-sec-title">` 渲染，滚动/分页共用。

### #5 目录跳章后往下滚，反而跳回前面几章

- **现象**：目录跳到第 396 章，往下滑第一下就跳回 388 章。
- **根因**：为支持"向上滚接上一章"，补章逻辑写成"滚动位置接近顶部就补"，且不判断方向。跳章后 `scrollTop = 0`，第一下滑动即被判成"到顶"，一路把 395、394… 前置，并把当前章更新成旧章。
- **修复**：
  1. 按滚动方向触发（向下才追加、向上才前置）；
  2. 跳章后 0.9 秒冷却 + 重置滚动基准；
  3. 前置时用"新增高度差"补偿 `scrollTop`，视觉不跳。

### #6 分页模式从第 N 章左点回上一章，落在章首而不是末页

- **现象**：章首左点应到上一章最后一页，实际停在上一章第一页。
- **根因**：重写滚动模式时把 `gotoEnd` 分支弄丢了——store 里仍在设置标志，页面测量 effect 里不再消费。
- **修复**：补回 `gotoEnd` 分支，并把落位**延后一帧**再测量一次，避免换章瞬间把总页数算成 1 而落到首页。

### #7 退出重进，页码差一页

- **现象**：在第 3 页退出，重进回到第 2 页。
- **根因**：锚点只存"页首段落 block"。一个段落可能从前一页跨到这一页，用 block 反算页码时退回了上一页。
- **修复**：锚点增加 `page` 字段，重进优先按页码还原；书签/笔记仍用 block（它们本就是段落语义）。

### #8 重进时用旧状态抢先渲染

- **现象**：修好 #7 后仍偶发回到第 1 页。
- **根因**：`ReaderBody` 在 `open()` 完成前就挂载了（store 里还留着同 id 的旧章节），先消费了锚点，随后 `open()` 重置 `page: 0`。
- **修复**：加 ready 门——`open()` 完成前只渲染加载态。

### #9 跨多页跳转时"正文整体偏左"

- **现象**：目录跳转或回末页时，截图里文字整体左偏。
- **根因**：`translateX` 从第 1 页一路动画到第 5 页，动画过程中看到的是中间页的错位；多页跳转本不该有过渡。
- **修复**：页差 >1 时加 `.instant`（`transition: none`）直接跳到位；舞台加 `overflow: hidden` 兜住瞬时溢出。实测静止状态几何始终是 `20 → 370`，无偏移。

## 二、React / 状态

### #10 React error #185（Maximum update depth exceeded）

- **根因**：`useMarks((s) => book ? s.byBook[id] ?? [] : [])` 每次返回新数组，zustand 认为状态变了 → 无限重渲染。
- **修复**：选择整个 `byBook`，再用模块级常量 `EMPTY_MARKS` 兜底。

### #11 TDZ：Cannot access 'book' before initialization

- **根因**：selector 里用了后面才声明的 `book`。
- **修复**：把依赖 store 的 selector 移到 `book` 声明之后。

### #12 快速切换书籍时显示上一本

- **根因**：异步 `open()` 竞态，旧请求后返回覆盖新状态。
- **修复**：`openSeq` 序号守卫 + 只在 `book.id === bookId` 时渲染 + `key={book.id}` 强制重建。

## 三、导入与解析

### #13 PDF 导入报 detached ArrayBuffer

- **根因**：pdf.js 会 transfer（转移）传入的 ArrayBuffer，之后原 buffer 失效；而我们还拿它去写文件。
- **修复**：交给 pdf.js 前先 `bytes.slice()` 复制一份。

### #14 PDF 阅读页一直卡在加载

- **根因**：渲染门先检查 `chapter` 是否存在，而 PDF 没有章节。
- **修复**：先判断 `book.format === 'PDF'` 走专用阅读器，再判断章节。

### #15 桌面版导入备份报 ENOENT

- **根因**：空数据目录下 `books/<id>/` 不存在，直接写文件失败。
- **修复**：写文件前 `mkdirSync(dir, { recursive: true })`。

## 四、安卓原生

### #16 启动页闪退（打开后刚铺满就退回桌面）

- **现象**：启动画面出现约 2 秒后闪退回桌面。
- **根因**：`SplashActivity extends AppCompatActivity`，主题却是 Capacitor 默认的 `Theme.SplashScreen`（父级是 `android:Theme.DeviceDefault.*`，不是 AppCompat），抛 `IllegalStateException: You need to use a Theme.AppCompat theme (or descendant) with this activity`。
- **修复**：启动页改用普通 `Activity` + 自定义 `SplashTheme`（AppCompat NoActionBar + 纸色背景）；`setContentView` / `startActivity` 套 try/catch 兜底，保证任何情况都能进书架。

### #17 启动后白屏（旧 WebView）

- **现象**：模拟器启动页之后空白，logcat 报 `ReferenceError: Iterator is not defined`。
- **根因**：pdf.js 顶层代码执行 `typeof Iterator.prototype.join`，而 `Iterator` 是 Chrome 122+ 才有的全局对象；旧 WebView 直接抛错，整个 React 起不来。
- **修复**：pdf.js 改为动态 `import()`（单独 chunk，只有打开 PDF 才载入）+ 构建 target 降到 `es2020`。

### #18 音量键翻页无效

- **根因**：Capacitor 8 的插件必须在 `super.onCreate()` 之前 `registerPlugin()`；且需要在 `dispatchKeyEvent` 里拦截并消费按键。
- **修复**：`MainActivity` 注册插件 + `dispatchKeyEvent` 判断"插件已启用 + 音量键 + ACTION_DOWN"才消费，其余交还系统；退出阅读页把启用标志关掉。

### #19 通知栏/锁屏控制不显示

- **根因**：Android 12+ 通知需要 `POST_NOTIFICATIONS`；前台服务还要 `foregroundServiceType="mediaPlayback"` 与对应权限。
- **修复**：补权限声明，首次朗读时动态申请；`TtsService` 用 `MediaSession` + `Notification.MediaStyle` 构建三键通知。

### #20 升级后界面逻辑还是旧的

- **现象**：APK 里已经是新逻辑，手机上行为却是旧版（例如导入仍报"没找到 model.onnx"）。
- **根因**：Android WebView 缓存了 `index.html` 与旧 JS 文件，覆盖安装后仍加载缓存。
- **修复**：启动时 `setCacheMode(LOAD_NO_CACHE)` + `clearCache(true)`；同时在设置里显示版本号，便于确认装的是哪一版。

## 五、朗读（踩坑最密集的一段）

### #21 点「听」直接开始朗读（早期设计）

- **修复**：交互改为"点「听」只展开面板 → 点 ▶ 才开始"，并可收成悬浮球。

### #22 点「听」完全没反应

- **现象**：点了之后没有任何界面变化。
- **根因**：为了预合成，把"合成死循环"提交到了与 `prepare()` **同一个单线程执行器**，`prepare` 永远排在死循环后面 → Promise 永不 resolve → 面板不出现。
- **修复**：合成循环移到独立线程（`wuya-local-tts`），`prepare` 作为队列任务在合成线程执行；JS 侧加 4 秒超时，超时先用系统 TTS 起步。

### #23 每句之间停 10–18 秒

- **现象**：第一句读完，等十几秒才出第二句。
- **定位**：把用户录屏的音轨抽出做静音检测，得到 1.7 秒语音 + **18.3 秒静音**的周期；说明不是"预取没生效"，而是合成本身太慢。
- **实测**（同一句，PC 上跑 sherpa-onnx）：

  | 模型 | 耗时 | RTF |
  |---|---|---|
  | MeloTTS zh_en int8 | 5617 ms | 1.32 |
  | Piper zh_CN-huayan x_low | 114 ms | 0.03 |
  | Matcha zh-baker | 265 ms | 0.05 |

- **修复**：换 Piper / Matcha 音色包（RTF 降两个数量级）+ 播放时预取后续 3 句 + 合成线程数按核数自适应（2–4）。

### #24 预取不生效（跳过了所有预取任务）

- **根因**：预取任务带 `token`，每次 `speak` 都会 `token++`，导致刚排进去的预取任务被判为过期丢弃。
- **修复**：预取任务不再按 token 过滤，只在 `stop()` 时清空队列；用 `playingId` 守卫防止旧音频回调误触发 `done`。

### #25 音色包导入报「压缩包里没找到 model.onnx」

- **根因**：为省体积换成 int8 量化模型，文件名是 `model.int8.onnx`，而导入代码只认 `model.onnx`；另外 Windows 打的 zip 里目录分隔符是反斜杠，Android 上会被当成文件名的一部分。
- **修复**：任意 `.onnx` 都算模型；导入时把 `\` 归一成 `/`；错误信息列出包里实际文件，便于排查。

### #26 导入 75MB 音色包直接闪退

- **根因**：JS 侧 `JSZip` 解压 + base64 转码 + Capacitor 桥接，峰值内存约 250MB，WebView 被系统 OOM kill。
- **修复**：改为**原生流式解压**——系统文件选择器（SAF）→ `ZipInputStream` → 64KB 缓冲写入 `files/tts/melo`，全程内存几 MB。

### #27 导入卡住 3 分钟，之后导入按钮失效

- **现象**：选择文件后一直"处理中"，取消选择后按钮再也点不动，只能重启 App。
- **根因**：Capacitor 8 里 `startActivityForResult(call, intent, int)`（旧 API）依赖插件预注册请求码，否则 `handleOnActivityResult` **一次都不会被调用**。于是解压根本没开始、Promise 永不结束、`modelBusy` 永久为 true。
- **修复**：改用 Capacitor 8 的正确姿势——`@ActivityCallback` 注解的方法 + `startActivityForResult(call, intent, "onZipPicked")`；取消也 resolve；解压过程上报进度事件（`importProgress`）并在 UI 显示「正在解压：N 个文件 / M MB」。

### #28 本地音色像"河南口音"

- **根因**：Piper x_low 是 16kHz、最小体量的中文模型，腔调被放大。
- **修复**：换 Matcha zh-baker（标贝女声，22.05kHz，标准普通话），RTF 仍只有 0.05，不会回到停顿问题。

## 六、跨端与打包

### #29 打包时 EBUSY：win-unpacked 被占用

- **根因**：上一次打包出来的 `无涯.exe` 还在运行。
- **修复**：打包前结束同名进程，或先退出应用。

### #30 国内网络拉不到 Electron / Gradle / Maven

- **修复**：
  - Electron：`ELECTRON_MIRROR`、`ELECTRON_BUILDER_BINARIES_MIRROR` 指向 npmmirror；
  - Gradle 发行版：`distributionUrl` 换腾讯镜像；
  - Maven：`build.gradle` 加阿里云仓库；
  - 模型下载：HuggingFace 用 `hf-mirror.com`，GitHub Releases 用 `gh-proxy.com`。

### #31 项目路径含中文导致 Gradle 报错

- **根因**：Gradle 对非 ASCII 路径有检查。
- **修复**：`android/gradle.properties` 加 `android.overridePathCheck=true`。

### #32 Capacitor 8 构建要求 JDK 21

- **现象**：`languageVersion=21` toolchain 报错。
- **修复**：安装并使用 Microsoft OpenJDK 21，`JAVA_HOME` 指向它。

### #33 APK 体积膨胀

- **根因**：sherpa-onnx 四套 ABI 的 JNI 库约 31MB/套。
- **修复**：`ndk { abiFilters 'arm64-v8a' }`，只保留主流手机架构；音色包不随 APK 分发。

### #34 用 PowerShell 批量改代码时注入字面 `\n`

- **现象**：改完 TS/CSS 出现语法错误，文件里多了真实的 `\n` 字符。
- **修复**：改用 Node 脚本（`fs.readFileSync` + `replace` + `writeFileSync`）做批量替换，双引号/换行都可控。

## 七、经验小结

1. **先测量，再排版**：字体、容器尺寸没就绪时任何计算都不可信。
2. **区分"没生效"和"太慢"**：用数据说话（抽音轨、量 RTF、看 logcat），否则容易在错误方向上优化。
3. **平台 API 要看源码**：Capacitor 8 的 ActivityResult、WebView 缓存、前台服务权限，文档没写清楚的地方，直接读 `node_modules/@capacitor/android` 的 Java 源码最快。
4. **大文件不要过 JS**：超过几十 MB 的二进制，交给原生流式处理。
5. **给用户留"证据"**：界面显示版本号、导入显示进度与预热耗时，能省掉大量来回排查。
